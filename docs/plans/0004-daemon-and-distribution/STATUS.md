# Plan 0004 — Daemon and Distribution — ✅ Done

The roll-up row in [../STATUS.md](../STATUS.md) must stay in sync with this file. Task-level truth lives in [tasks/](tasks/) frontmatter; Makina's integration coordinator updates both layers.

- **Status:** ✅ Done.

- **Goal:** land the `iznik-server` daemon — paths, lock, socket, detach, idle shutdown, logging, multi-client connections, and the `--stdio` relay — the integration harness every later test uses, a committed performance baseline, and reproducible static artifacts for both Linux targets.
- **Root cause:** a session that lives only as long as a connection is a session a network blip destroys; only a process that outlives every client, reachable through a relay that starts it, makes reconnect the whole cost of a drop.
- **Approach:** a test client that speaks the real protocol over any duplex stream, landed first so nothing is hand-rolled twice; a connection loop proven over a socket pair before the daemon that accepts for it; a daemon indifferent to attachment, proven to survive the SSH session that started it inside the host container; a relay that is the one thing the bootstrap ever runs; an in-process stack so no test guesses a binary's path; and numbers, committed with the machine described.
- **Progress:** 9/9 tasks done; 0 blocked; 0 dropped.
- **Integration:** `planned`; run —; base `develop`; validation base —; mode —; final integration —.
- **Exceptions:** `test-client` records one: `TestClient::snapshot_request` is not in the architecture's list for that section. It is the send half of `snapshot`, and the golden sweep needs it — `snapshot` waits for the reply, while a fixture line is one frame and not a conversation; `snapshot` is written in terms of it.


  `client-connections` records four of its own, three of them in files it does not own, landed with it. `serve` does not take the history budget the architecture's signature lists: the registry owns it, and a parameter nothing reads is worse than none. `Registry::signal` is new, because the registry ingests by pulling and nothing was telling anyone when to pull — a resize, a title or an exit on a pane nobody is subscribed to was a delta that never arrived, and `daemon-lifecycle` needs the same signal to notice its last pane going. `Multiplexer::reply` and `send_snapshot` are new, because a connection's own answers must go out through the thing that owns the sink, and a snapshot in particular must go through the pump or the generation it carries is not remembered. `MultiplexerError::UnknownChannel` and `ChannelTable::awaiting` are new, to separate a client crediting a channel it never had — which this plan requires be refused — from one crediting a channel just detached, which is the race the release handshake exists for. `RegistryError` moved to `session/mod.rs` and is re-exported, so its path is unchanged: `commands` maps it to a rejection code, and `registry.rs` was at the thousand-line limit.

  It pumps one round per turn rather than to exhaustion, which the writing of its own last case forced: a flooding pane whose client keeps returning credit starves every request on the connection otherwise, and a keystroke would wait for the flood to end.

  `daemon-lifecycle` records two. Its log writes through the runtime rather than through `tracing-subscriber`'s file writer: that writer wants `std::io::Write`, which section 3.6 forbids under this crate, so a layer formats each event into a line and one task owns the file — and the same reason makes the lock write its process id through the path rather than through the handle it holds. And `DaemonOptions::parse` is public beyond the architecture's list, because the task asks that the default interval be asserted from a parsed command line rather than by waiting for it.

  Its review left the connection loop three fixes that are properly `client-connections`': the reader now notices its dispatcher ending, a `JoinError` is no longer a clean disconnect, and a pane that ends keeps raising the registry's signal for as long as the reaper needs to say how — the last of which is what makes a pane's going reach a client with no daemon behind it. Both new cases are in `client_connections.rs`.

  `stdio-relay` records one, in a file it does not own: `main` shuts the runtime down in the background rather than dropping it. The relay reads standard input on a blocking thread, and a client that has stopped writing leaves that read parked for ever — dropping the runtime waits for it, so a relay whose daemon had gone hung holding a terminal open. Every entry point has said what it has to say and flushed it by then. It also reads the architecture's "`copy_bidirectional` until either side closes" as the asymmetry it has to be: a client's end is a half-close and what the daemon answers is still delivered, while a daemon's end is the relay's end. `copy_bidirectional` waits for both, and a relay written on it hangs on a dead daemon.

  Workstream 0016 is complete with it, and its scenarios and `daemon-lifecycle`'s run over real SSH in the fixture.

  `integration-harness` records one, and it is a reading rather than a departure: `expect_reassembly` compares what a scenario captured against the pane's *own* screen, asked for at the moment of comparison, rather than against a separately captured unbroken reference stream. The architecture's words allow either; this one needs nothing kept in step between two connections and fails on any difference the server would see, which is what the claim is about. `STARTUP_CEILING` lives in `stack.rs`, where the thing it bounds is, and `performance-baseline` takes it from there.

  `performance-baseline` records one: `tests/regression_baseline.rs` includes `benches/baseline.rs` with a path attribute, so one definition of how a figure is taken is printed for a person there and held to a ceiling here. Cargo builds a benchmark with `cfg(test)` set, so nothing in that file can tell the two builds apart — the test makes the included module public and names the benchmark's entry point rather than the file guessing which build it is in. Workstream 0017 is complete with it, and the measured table is in `docs/notes/baseline.md`.

  `linux-artifacts` records four. `RUSTFLAGS` replaces every configured flag rather than adding to them, so `linux.rs` reads `build.rustflags` and `target.<triple>.rustflags` out of `.cargo/config.toml` and passes them on beside its own remapping: without that the musl targets lose `link-self-contained=no`, link rustc's startup objects beside the cross-compiler's, and fail on a duplicate `_start` — a reproducible build that does not build is not one. `.config/nextest.toml` gained a `distribution` test group of one thread, a file this task does not own, because two release builds at once wait on each other for cargo's package-cache lock and one of them times out. `xtask/src/distribution/darwin.rs` and its lexicon land here rather than with `darwin-artifacts`, because `mod.rs`'s dispatch names `darwin::TARGETS` and will not build without them; the rest of that task is its own. And `Lock::acquire` became asynchronous, in `daemon-lifecycle`'s file: it now asks again after a pause when the lock is momentarily held by the shared-mode probe that reads the holder's process id, and section 3.6 forbids this crate to sleep a thread to wait for anything.

  Its own review left `performance-baseline` two fixes and `daemon-lifecycle` one. The daemon takes a `--program`, so a measurement runs a named shell rather than whoever's login shell is on the machine — a baseline of `fish` and a baseline of `sh` are not the same number. Throughput is timed from the first byte out to the last byte in rather than around the whole exchange, and resident memory is sampled after the figure has settled rather than at a fixed moment. And a pane that ends is looked for twice as many times as `ingest` needs, because a notification landing on a permit that is already there is a look nobody takes.

  `darwin-artifacts` records two, and answers its gate. The gate asked how a Darwin toolchain is provided; the answer is that it is not provided here at all — the artifacts are built on a macOS runner, where the SDK is the system's own, and `.github/workflows/darwin-artifacts.yml` sets `SDKROOT` from `xcrun --show-sdk-path` before building. A Linux machine gets the refusal instead, which names the variable and the workflow. Someone who would rather build these on a Mac under a desk has the same two things to satisfy, written out in the module header: the SDK and that variable, plus a cross linker if the machine is not itself a Mac.

  The second is an addition rather than a departure. The task's dynamic-link case is deferred to a Mac, and a load-command walk that silently found nothing would pass there with the allowlist never consulted — so the walk reads bytes rather than a file, and a third claim proves it here against a synthetic Mach-O file naming two libraries and a file that is not Mach-O at all. Workstream 0018 is complete with it.

  Both artifact tasks were reviewed together afterwards, and what that found is recorded here because most of it was a proof that could not fail. The reproducibility case built the same commit twice against a warm cargo fingerprint, so the second build relinked nothing and the comparison held whatever the compiler did; it now throws the package's build products away between the two. The claim said "stripped" and nothing looked: the ELF section headers are read for a symbol table now, and a header table that cannot be walked is an error rather than an answer of "statically linked and stripped". The Mach-O walk was proven against a file of nothing but library commands, so the step across a command of another kind and length — which is most of a real one — was never taken; there are segments around and between them now, and a file whose commands run past its end is refused. The size assertion restated what the producer already refuses, so it asserts instead that the number recorded is the file's own.

  The producer had four of its own. Two builds of one commit agreed only on one machine: a dependency's panic locations carry the absolute path of the registry it was unpacked into, which strip does not remove, so the registry and the git checkouts are remapped beside the workspace — and the flags are set through `CARGO_ENCODED_RUSTFLAGS`, the second review's doing recorded below, with `RUSTFLAGS` removed from the child's environment so a caller's cannot look as though it applied. An unreadable `.cargo/config.toml` fell through to no flags at all, which is exactly the duplicate `_start` the reading exists to prevent, so it is an error now. A manifest whose protocol version could not be scraped shipped a `0`; it is a failure. And an artifact over the ceiling was copied before it was measured, leaving a half-written distribution directory behind.

  `xtask claims coverage` — every proof in the registry at once, which nothing had run since the distribution cases landed — then found one more, and it is the distribution cases' own. A release build of this workspace is fat link-time optimization at one codegen unit and takes every core there is; beside it, `pane_many_share_one_thread` waited twenty seconds for a shell to print a prompt and did not get one, and `fidelity-suite::flood` went the same way. The distribution binaries run with the machine to themselves now, and both pass — the first in sixteen milliseconds rather than timing out at twenty seconds.

  The workflow had three, each of which would have failed on the first run: only the matrix triple was installed while the case builds both, the emulator's Zig is not on a macOS runner, and neither is nextest. And `.config/nextest.toml` gave every `regression_*` binary ten minutes, which is a third of what a cold release build of two musl targets is budgeted; the distribution binaries get an hour, in an override placed before the general one because nextest takes the first that matches.

  `performance-baseline` took two more. Resident memory was sampled the instant after fifty panes were made, while fifty shells were still allocating, though the note said it was sampled once they had stopped; it is asked again every hundred milliseconds until two answers agree. And the figures are re-measured and committed on their own, after the code they measure, so that "the commit that records them changes nothing they measure" is true rather than nearly true.

  `integration-harness` took one: a `Stack` in binary mode dropped a program's arguments, because `--program` takes a path and nothing after it, so the two daemon modes would have run different things. It refuses now instead.

  `daemon-documentation` records four, and the first is why the other three exist. Its done-when is that every command a README names answers `--help` with exit zero, and none of them did: `xtask check --help` ran the gate, `iznik-server --daemon --help` started a daemon, and `iznik-regression step --help` waited on standard input for a step that was never coming. Every subcommand of all three binaries answers now, ahead of doing anything, including the two whose work has not landed — a named command that cannot say what it is has already drifted from the document that names it.

  The other three follow from writing the test. It is two files, `xtask/tests/readme_commands.rs` and `crates/iznik-server/tests/readme_commands.rs`, neither in this task's `touches`, because `CARGO_BIN_EXE_` resolves only inside the package that owns the binary. And `iznik-server` gained `iznik-harness` as a development dependency, for its bounded process runner alone: section 8 says no spawned process runs without a deadline, and a `--help` that hung would otherwise hang the suite.

  Workstream 0019 is complete with it, and plan 0004 with that.

  A second review of both artifact tasks and `daemon-documentation` found ten more, and the first was a regression this session had introduced: the ELF walk read a program header's type where a *section* header carries it, which in a 64-bit file is the flags word — so "it names no loader" was true of every input, a dynamically linked binary included, and the static-linking claim was vacuous. The two tables are read at their own offsets now, and a synthetic ELF file with a `PT_INTERP` in one and a symbol table in the other proves it: putting the offset back where it was fails that case. `/bin/ls` carries the type at zero and nothing at four, which is what settled it.

  Four more were of the same kind. `CARGO_ENCODED_RUSTFLAGS` is set rather than `RUSTFLAGS`, because the remapping this now adds contains a home directory's path and a whitespace-joined flag list would split `/Users/John Doe` into two arguments and fail the build. The distribution directory is cleared before the build rather than after a refusal, since an earlier build's is complete, verifies against its own checksums and uploads exactly as though it were this one's — and any failure, a missing cross-linker as much as a size ceiling, must not leave it there to be taken for the answer. The distribution cases' deadline was sixty minutes where the case may legitimately spend sixty-one inside its own. And `settled` gave up quietly after two seconds and returned a moving figure, while `baseline.md` said the number could not be one — it is an error now, over a window widened to ten seconds so that giving up means something did not settle rather than that the machine was busy.

  The rest were the documents and the proofs about them. `iznik-regression` gained a `readme_commands` of its own, so "each binary" is three of three and `step --help` is held to answering rather than reading standard input. The platform-alias proof was a tautology on Linux — `is_this_platform("darwin")` and `is_this_platform("macos")` are both false here — so the resolution takes both sides as arguments and is asserted directly. `xtask`'s document parser anchors on a code span like its sibling, so a sentence that happens to say "cargo xtask runs the gates" is not a command called `runs`. And the manifest's protocol version is compared against what the source declares rather than merely against zero, which nothing could produce any more.

  A third review, of those fixes, found twelve more — none of them a regression this time, and four worth naming. `clear` ran only on the oversize path, so any other failure left a complete and uploadable directory from an earlier build; it runs before the build now and reports what it cannot remove rather than swallowing it. The synthetic-ELF case was not ignored, so it sat in a `regression_` binary and demanded the whole machine on every ordinary run: the ELF and Mach-O readers moved into `xtask::distribution::shape`, and the files made to have each shape are proven in `artifact_shape`, which builds nothing and runs in the gate. The `readme_commands` rule was three copies of one thing that had already drifted in one respect, and is now `iznik_harness::documents` with three callers. And the manifest's protocol version is read by the producer's own function rather than a second scrape written beside it, compared with the newline that makes `1` not a prefix of `10`.

  The rest were prose that had stopped being true of the code beneath it — a comment saying an hour where the value said ninety minutes, a doc reasoning about the variable its function no longer sets, an exception in this file saying the opposite of what `linux.rs` does — and the magic numbers in a synthetic file's identification bytes, which are named now.

  `client-connections` inherits an obligation from plan 0003's `multiplexer-assembly` review, recorded there and in `regression/claims/multiplexer-assembly.toml`: five fixes on paths an in-memory sink cannot reach — a delta returning to its queue rather than vanishing, a mark staying the only copy of itself, a subscription that fails before announcing its channel freeing the number outright, a pane that cannot answer detaching one pane instead of the connection, and a forgotten pane's queued marks going with it. A real link can refuse a frame; that is where each must be proven.
- **Outcome:** A daemon that survives disconnection and the shell that launched it, serves several clients at once with per-client focus and clean teardown, is reached through `iznik-server --stdio` over real SSH from the engine container, has committed numbers for latency, throughput, memory and startup, and ships as one reproducible static binary per Linux target.
