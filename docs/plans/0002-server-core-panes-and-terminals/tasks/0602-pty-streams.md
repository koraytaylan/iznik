# PTY Streams

The one module in the server where blocking I/O exists, named by the policy gate: it turns the pseudoterminal's blocking descriptor into an async output stream and an input path on dedicated blocking threads. Its two promises are that a slow consumer stalls only its own child, and that bytes submitted in one call are written whole — bracketed paste and multi-byte key encodings survive by construction.

**Steps:**

1. Implement `crates/iznik-server/src/pty/streams.rs` — `streams`, `OutputStream`, `InputHandle`, `InputError`, and the constants `READ_CHUNK_LENGTH`, `OUTPUT_CHANNEL_CHUNKS`, `MAXIMUM_PENDING_INPUT_BYTES` — exactly as the architecture's `pty-streams` section specifies.
2. Write `crates/iznik-server/tests/pty_streams.rs`, its children `cat`, `sh` and generated data from `iznik_testkit::corpus::generated`.
3. Declare this task's claims in `regression/claims/pty-streams.toml` as `test` proofs with their `because`.

**Tests:**

- Byte identity: a `cat` fed 16 MiB of generated bytes is read back byte-identical, whatever chunk boundaries the stream chose, in under three seconds.
- Atomicity: one hundred concurrent tasks each writing a distinct 4 KiB pattern to a `cat` child produce output in which every pattern is contiguous.
- Backlog, not loss: with the child stopped by `SIGSTOP`, writes beyond `MAXIMUM_PENDING_INPUT_BYTES` return `Backlog { pending }`; after `SIGCONT`, every accepted byte arrives in order and nothing was dropped.
- End of stream: when the child exits, `next` returns `None` after the last byte, never before.
- Isolation: two children, one whose output nobody reads, one echoing keystrokes — the echoing one's round trip stays under a stated budget while the other's reader is blocked.

- **Done when:** `timeout 600 cargo nextest run --package iznik-server --test pty_streams` passes every case above, `timeout 900 cargo xtask claims verify --task pty-streams` reports every claim proven, and `timeout 3600 cargo xtask check` succeeds.
