# Plan 0003 — Session Model and Multiplexer — ✅ Done

The roll-up row in [../STATUS.md](../STATUS.md) must stay in sync with this file. Task-level truth lives in [tasks/](tasks/) frontmatter; Makina's integration coordinator updates both layers.

- **Status:** ✅ Done.

- **Goal:** land the golden-pinned host model, deltas, reconciler and command vocabulary; the server's session registry and command applier; the channel multiplexer with credit-based scheduling; resume with `Screen` as the single resynchronization; and negotiated streaming compression.
- **Root cause:** a client needs identity, arrangement, titles and directories that stay true across reconnects and across other clients, and one link per host needs arbitration so a flooding pane cannot starve a keystroke.
- **Approach:** mint identity once and derive position; emit numbered deltas directly from the operations that cause them and prove convergence by fuzzing with one shared generator; land the channel table, the resume decision and the compression layer as pure pieces before the pump that assembles them; treat each subscription as a cursor into the history ring so the multiplexer buffers nothing; and hold the scheduler to a measured latency figure under a flood.
- **Progress:** 10/10 tasks done; 0 blocked; 0 dropped.
- **Integration:** `planned`; run —; base `develop`; validation base —; mode —; final integration —.
- **Exceptions:** `model-types` added two things to files plan 0001 owns, landed with it and reviewed, because a caller cannot be written against a callee's specified surface without them: `iznik-protocol`'s private `wire` module gained a `Reader::payload` constructor, since a model payload carries no discriminant and `Reader::new` consumes the first byte as one, and a `put_count`/`Reader::count` pair, so the element count every session-model payload carries is written and read in one place; and `MessageError` gained `LayoutTooDeep`, since a recursive-descent decoder over a nesting the wire does not bound is a stack overflow a peer can ask for, and this crate keeps one vocabulary for what a decoder found. `MAXIMUM_LAYOUT_DEPTH` (64), refused by the decoder on the way down and by the encoder and the validator alike, is `model-types`' own addition beyond the architecture's list for that section; the words all of it introduces are in `policy/lexicon/model-types.txt`, attributed to the task that introduced them. It leaves `session-registry` and `session-commands` an obligation: an operation that would nest a layout past the bound is refused with `InvalidLayout`. Review of the task added three more, all in its own commit: normalization also divides a split's weights by the factor they share, without which the product a flattening multiplies by accumulates until it saturates and the same arrangement is two different trees, which is exactly what the architecture stakes the reconciler's equality test on; `ModelError::EmptySplit` names the one shape normalization cannot remove — a split holding nothing, at the root, where there is no parent to drop it into and no child to collapse it to — so `set_layout` refuses it rather than storing a layout that places no pane; and `message::NO_DISCRIMINANT` is what a payload carrying no tag reports, since `Hello`'s discriminant is zero and a refusal inside a `Snapshot`'s model was being printed as a refusal of the handshake.

  `deltas-and-reconciler` records four of its own. It widens `model.rs`'s writers, readers and per-part validators to `pub(crate)`, outside its touches, because the delta payload embeds a session, a tab, a pane and a layout and the reconciler holds each to the same invariants `validate` does — one definition of how a model value is written and one of what makes it valid. It reads the task's "every intermediate model validates" as *between changes*, not between the deltas of one change: the architecture makes each variant the smallest thing that can happen and the registry emit `PaneAdded` then `LayoutChanged`, so a model between those two deltas holds a pane its layout does not place, and a reconciler that refused it would refuse the sequences the registry is specified to emit — the generator therefore yields changes of one or more deltas and the property validates where a change ends. The registry-operation generator names its targets by position rather than identity, resolved by `generate::chosen` against the model as it stands, because a registry mints its own ids and a sequence generated before it runs cannot know them; `session-registry` is its first consumer and may need it adjusted. And the `ExitStatus` decoder refuses a tag no variant claims before reading its value, which the golden caught reporting bytes running out instead.

  Review of `deltas-and-reconciler` added a rule the whole crate now keeps and `session-command-codec` was written to: an encoder refuses a layout its own decoder would turn away, by an exhaustive match, because a delta or a command a client cannot decode is a client that can never catch up. `model.rs` owns the guard and the direction's wire mapping; `wire.rs` owns the optional string all three payloads carry. `session-command-codec` records one exception of its own: `crates/iznik-protocol/src/model.rs` and `src/wire.rs` are outside its touches for those two, landed with it.

  `channel-multiplexer` defines `SinkError` and `MultiplexerError::NotReleased` beyond the architecture's list for its section: the former because `MultiplexerError::Sink(SinkError)` is its own and a caller cannot edit a callee's file, so `multiplexer-assembly` finds the type already there; the latter because the task asks for a refusal that names the channel and no listed variant names one. `CreditWindow::widen` and `narrow`, and `Cursor::lag`, are there for the same reason — the pump moves focus and marks a cursor stale, and cannot reach into these files to add them.

  `stream-compression` records what the ratio number turned out to mean. The fidelity corpus is 316 bytes of payload across seventeen constructs, which is far under the hundredfold `zstd --train` asks for and it says so; the 378-byte dictionary it settles on nonetheless takes the corpus to 101 bytes, a ratio of 3.129 against the plan's 3.0. That ratio is the corpus *as data*. As the link frames it — seventeen frames, a flush after each, which is what the latency number buys — it costs 299 bytes against 411 uncompressed, a saving of 1.375. Both are in the ratio test's assertion so neither can be quoted alone. The latency number is comfortable: 740 nanoseconds added at the ninety-ninth percentile against a one-millisecond ceiling.

  `session-registry` records four. It holds the budget behind a `Mutex`, because `HistoryBudget`'s methods take `&mut self` and an `Arc` alone cannot reach them. It ingests by pulling rather than subscribing: a registry lives behind a lock, and a task that took that lock on every mark would need a handle to the lock the registry cannot hold until the lock exists, so whoever owns it calls `ingest` when a pane signals. It checks the model after every operation rather than asserting it, because §3.5 forbids dying of a bug that could be a logged error and the tests are what fail on it. And it needed three accessors `Pane` did not hand out — `state_updates`, `exit_status_now` and `set_history_capacity` — landed in their own commit, the last of which closes a gap between plan 0002's `history-ring` and `pane-assembly`: the budget held rings nothing appended to, so its eviction bounded nothing.

  `multiplexer-assembly` records six. `Multiplexer` is generic over `Sink: FrameSink` where the architecture writes `sink: Box<dyn FrameSink>`, and `FrameSink::send` returns `impl Future<Output = …> + Send` where the architecture writes `async fn`: an async trait method is not dyn-compatible, and boxing a future per frame would sit on the byte path the whole task is accepted on. It adds two things to files outside its touches, landed with it: `MultiplexerError::Encoding` with a `From<MessageError>` in `channel.rs`, because the pump encodes every control message and had nowhere in its own vocabulary to put a refusal; and `Pane::copy_history(from, limit, out)` in `pane.rs`, because `read_history` allocates a fresh `Vec` and takes no limit, while the architecture requires one frame's worth copied into a buffer the pump owns. A `Screen` is serialized *before* the `PaneChannel` that announces it, and the channel carries `screen.sequence` rather than the sequence the plan asked for: the mirror can advance between deciding and serializing, and the contract is that the bytes which follow begin exactly where the screen ends. Its own review found that a `ScreenRequest` on a live subscription rebuilt the cursor and so handed out a window the client had never granted; the credit is a property of the channel and is now carried over. And its thirteen listed cases are eight `#[test]` functions rather than thirteen — fan-out's three clauses are one case, cold attach and the screen request are one, the two resume answers are one, fairness and focus are one, and credit, memory and the idle interval are one — because the file is at the 1000-line limit and every clause is still asserted separately; the claims file names which case proves each.

  `session-documentation` records one, a strengthening rather than a departure: its test bullet asks that every discriminant in `docs/notes/protocol.md` match the constant of the same name in `message.rs`, and `protocol_reference.rs` checks `model.rs`, `delta.rs` and `command.rs` too, since the reference publishes their tag modules as well. It also checks the other direction — a tag the crate declares and the document does not publish fails — because a second implementation that never learns of a discriminant is exactly as broken as one that learns the wrong value.

  `session-commands` records one: `apply` is `async`, where the architecture writes it as a plain function. Three of the eleven commands start a process, and a synchronous `apply` would either block the runtime that carries every other pane's bytes or lie about having started one. Workstream 0012 is complete with it.

  Review of `session-registry` found the shared history budget was charged for every pane ever created and credited for none, so a closed pane's four mebibytes sat ahead of every live pane in the eviction order and it was the long-lived pane's scrollback that paid — the fix gives the share back through a new `HistoryBudget::remove`, outside the task's touches. It also found that a pane whose reaper never records a status was never removed from the model at all, now bounded, and that `emit` swallowed a refusal while the create above it answered `Ok`. Separately, the suite's own parallelism was starving one shell-driving test per run past its twenty-second deadline; `.config/nextest.toml` now runs the server crate's tests four at a time, which is plan 0001's file and its own commit.

- **Outcome:** A server that holds an authoritative, reconcilable host model, answers every command exactly once, carries every subscribed pane over one link with the focused pane responsive under a flood, resumes a client from the byte it holds or the screen it needs, and compresses the link when the numbers say it should.
