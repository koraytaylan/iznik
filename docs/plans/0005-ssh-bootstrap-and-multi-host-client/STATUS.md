# Plan 0005 — SSH Bootstrap and Multi-Host Client — 🚧 In progress

The roll-up row in [../STATUS.md](../STATUS.md) must stay in sync with this file. Task-level truth lives in [tasks/](tasks/) frontmatter; Makina's integration coordinator updates both layers.

- **Status:** 🚧 In progress.

- **Goal:** connect the client engine to remote hosts over the user's own SSH configuration, bootstrap the server and terminfo where they are missing with an explicit upgrade policy, and hold several hosts concurrently behind a client-side model with optimistic commands — proven end to end from a bare engine container against two hosts through link drops.
- **Root cause:** the daemon speaks only to its relay, there is no client-side model in front of it, and multi-host identity cannot be retrofitted after a single-host model has shipped.
- **Approach:** shell out to `ssh` with `ControlMaster` so `~/.ssh/config` keeps working unchanged; probe, upload, verify, launch and never again, each stage driven from the engine container by a step of its own; never replace a daemon silently; key everything on global identity so a pane survives a host reconnect and the client resumes rather than rebuilds; and make every interval a field so a link-drop proof takes seconds.
- **Progress:** 11/13 tasks done; 0 blocked; 0 dropped.
- **Integration:** `planned`; run —; base `develop`; validation base —; mode —; final integration —.
- **Exceptions:** `ssh-control-master` records two. `SshTransport::arguments` is public beyond the architecture's list, because what the vector *lacks* is the property this task exists to hold — every option a person could have written in their own configuration — and asserting an absence needs the value, not a process. `SshTransport::spawn` and `close_master` are not `async`, though the architecture writes `spawn` that way: neither awaits anything, since `tokio::process::Command::spawn` is synchronous and what a caller waits for is the child — and clippy's `unused_async`, which this workspace denies, refuses an `async fn` with nothing to await. The signature the architecture asks for cannot be written under the lint set the same document requires. And `classify` takes the host as well as the status and the words, because every variant of `SshError` carries which host it is about and a classifier that did not know would have to be told twice.

  Its `HostKeyChanged` says "the host key was not accepted" rather than "is not the one remembered", because `ssh` prints `Host key verification failed.` both for a key that changed and for one that was never known under strict checking. The architecture's variants are fixed and both are the host's key rather than the network; the detail carried is the line that matched — its review's doing, recorded below — which says which it was, and the alarming sentence is conditioned on the first.
  Its review found ten, and the first was user-facing. `classify` read `ssh`'s words before its exit status, so a remote binary without its executable bit — which exits 126 saying "Permission denied" — was reported as the host refusing the credentials, and a person was sent to look at their keys for a file mode. The detail carried is the line that matched rather than the last line, because `ssh` ends both host-key failures with the same generic sentence and a first connection to an unknown host would otherwise read exactly like a key that changed under someone.

  Three more were about time. `ssh` takes whole seconds and a zero is not "at once" but "never" — `ControlPersist=0` keeps a master for ever — so a field under a second is rounded up rather than truncated into its opposite.   The rest: the runtime directory is refused unless it is a real directory this user owns, because the fallback is a predictable name in a shared temporary directory and `create_dir_all` follows a link — someone who planted one first would have had this restrict a directory of their choosing and then fill it with live SSH connections. And the module says, on the record, that three of the six options iznik owns are ones a person may also have written and that a command line beats their configuration.

  `remote-channel` records three. Its `RemoteChannel` holds the `SshChild` for its own life rather than only the pipes it took from it: the transport spawns with `kill_on_drop`, so letting the child go after taking its standard streams kills the very process those pipes lead to — which reads, from the other end, exactly like a host that closed the link, and did.

  Its step's vocabulary is the client step's narrowed rather than repeated. There is no `hello`, because opening a channel *is* the handshake, and nothing about reassembly, because that belongs to the step that has an oracle. What it gains instead is `pause_server`, and the reason is the driver's shape: every step is its own process, so a channel opened in one is gone by the next and a network fault between them would be met by the *opening* of a second channel rather than by the silence of the first. The step stops the daemon itself through the same alias — the relay stays up, the socket stays open, and nothing answers — which is the link this task is about, inside one step where it can be watched.

  And the wait drains before it judges: whatever was in flight when the server stopped is still coming, and delivering it is the channel doing its job. What is asserted is what happens when there is nothing left.

  Its review found twelve, and the first was a claim that was false about its own proof: it said the host's network was cut, and the scenario stops the daemon. The claim says what is done now, and the reason is recorded with it — the fixture applies a fault between steps, a channel cannot outlive the process that opened it, and neither container carries the traffic tooling to cut a network from inside one, so a stopped daemon over a healthy link is the same silence from the channel's side, which is the side this task is about. The rest of that Test — a network fault and a channel opened after it is cleared — is what `integration-harness`'s `reconnect-over-ssh` already proves one layer down.

  Three were bugs a caller would meet. `next` took its deadline as a race against the reader, and a reader with a frame always ready wins it every time — so a wait for something a flooding pane never says had no bound at all; the deadline is checked before each poll now. The ping held the shared writer across its send, which parks when the peer has stopped reading: exactly the moment the ping fires, so the lock was held for ever and every caller that wrote wedged instead of being told the link was dead. It never waits for the writer now, because a writer something else is using says as much as a pong. And the step's per-action patience was `timeout.min(DEFAULT_PATIENCE.max(timeout))`, which is `timeout` — the twenty seconds it documented never applied.

  Two were silence where there should have been words. The `ssh` child's standard error was piped and never read, so a host with no server at the path it was given closed the link and the channel could only say that it had closed, while `command not found` sat unread in a pipe — and a long session would have filled that pipe and stopped the remote process in a write. It is drained into a bounded tail now and carried in the error. And `await_bytes` with an empty needle called `windows(0)`, which panics.

  `optimistic-commands`' own review found eight, and the first two were the design rather than its details. What a command showed was applied to the one model the client holds, and the host then announced the *same change* to the client that had asked for it — so every close that worked was refused by the reconciler as a change the model could not take, and answered with a complaint and a request for the whole model. And a refusal restored a snapshot taken at submission, discarding every authoritative change that had arrived since and taking the generation back with it, so the next delta was a gap. Both are the same mistake: one model where there are two truths.

  There are two now. What the host has said is one model; what the client shows is that model with everything still in flight applied on top. A delta is applied to the first and the pending effects are put back over it — so the host never has to reconcile a change it has not made, a refusal never undoes one it has, and "the authoritative delta always wins" is a property rather than a hope. A case walks a rename, a close and a pane's whole cascade through the host's own announcement and finds the view unchanged.

  `connection-manager` records three. The manager's file passed a thousand lines, so the per-host task lives in `host/manager/task.rs` and the module is a directory — which this workspace's own lint requires of any module with children.

  `ManagerEvent` carries a pane's bytes. The architecture does not enumerate the event, and without them there is no way for anything above the manager to see a pane's output at all: the model holds a cursor, not a stream. It carries the byte position they start at with them, so that a client can see for itself that a stream carried on across a reconnection rather than beginning again — which is what the resume case asserts.

  And giving up on a command nobody answered is one task for the whole manager rather than each host's own. A host's task is in exactly one place at a time — connected, waiting out a backoff, part way through a bootstrap — and a promise about a clock must be kept in all of them. It touches only the model and its lock, so no host waits on another for it.

  The review of those three found twelve more, and the two that would have cost somebody their output were about a channel number. `arrived` advanced *every* subscription holding the number the bytes came in on, and after a reconnection a host re-announces resumed panes on whatever is free — so a pane not yet re-announced could still be holding a number that now belongs to another, and the bytes would move the wrong cursor. That pane would then resume from a byte it never reached: silently lost output, which is the one thing the cursor exists to prevent. A channel now belongs to one pane, the announcement says whose, and a stale claim is dropped when it is contradicted.

  Two were the probe answering about the wrong place. `terminfo` was one answer for the whole host while the prefix is one candidate of three, so an entry under a directory this user cannot write had the bootstrap reporting `<chosen>/terminfo`, which is not there — verbatim the failure the change one commit earlier was made to prevent. And it looked for `terminfo/x/xterm-ghostty`, which is ncurses' layout only where filenames keep their case: on Darwin, a supported host, `tic` writes `terminfo/78/…`, so every Darwin host would have answered no for ever.

  Two were about what a refusal points at. A channel's open covered both getting a link and being greeted on it under one deadline, so an unreachable host — blackholed, and slower to fail than the client's own budget — was reported as a server that had started and said nothing. The two halves are timed apart now, with a refusal of their own each. And `Reconnecting { attempt }` could never say anything but "attempt 1": every failure after the first landed in `Failed`, because the machine did not remember that it had once been connected. It does now, and a host coming back counts its attempts while one that never arrived says why it did not.

  Three were the address parser accepting what it would never write: `iznik://a/b/7` read as the host `a/b`, which renders as `iznik://a%2Fb/7`; `%+7` taken for an escape, because `from_str_radix` accepts a sign; and the empty alias, which the type admits and the parser refuses — recorded in the type's own documentation as the deliberate answer rather than left as a surprise.

  `iznik_protocol::reconcile::apply_change` is public now.   And `expire` takes the host as well as the view, because the notification the architecture names it as producing — `Notification::CommandTimedOut` — carries which host did not answer, and a view does not know its own alias.

  The address escapes everything outside RFC 3986's unreserved set rather than only the characters that would break the parse. An alias is whatever a person typed — `unix:/tmp/iznik.sock` holds a colon and two slashes, an SSH alias may hold a space — and the property that matters is that the string written into a log comes back as the host it named. Escaping conservatively costs some readability in a `unix:` address and buys an exact round trip for every alias there is.

- **Outcome:** Several remote hosts held at once over ordinary SSH, each bootstrapped automatically from a machine that had nothing, each surviving link drops without losing pane identity or bytes, with unambiguous commands applying instantly and reconciling against the server.
