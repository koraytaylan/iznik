# Architecture — Plan 0005

> The concrete deltas, by symbol. The system is described in the root [`ARCHITECTURE.md`](../../../ARCHITECTURE.md) §6; the rules and the way of working are in [`CONTRIBUTING.md`](../../../CONTRIBUTING.md). Read both before your first task. Every task here declares its claims in `regression/claims/<task-id>.toml`; a `test` proof carries its `because`.

## Three rules that decide most of this plan

**Never reimplement something `ssh` already does.** If a feature seems to require parsing `~/.ssh/config`, the answer is to pass the host alias to `ssh` and let it decide. Reading an alias to show it in a UI is fine; interpreting it to route a connection is not. The one alias form iznik interprets itself is `unix:<path>`, a daemon socket on this machine reached with no SSH at all — what every in-process test, the C smoke program and the plumbing commands use.

**The reachable SSH host is the fixture's host container, and nothing else.** No test starts an `sshd`, reads the developer's `~/.ssh`, or talks to `localhost` over SSH. A task whose tests are pure — the model, the reducer, the state machine, optimistic commands against a fake view — has no container proofs; everything that touches a network is a scenario run from the engine container, which carries no agent and no keys, because a bootstrap that only works on an already-configured machine is not a bootstrap. Each stage of the bootstrap is proven in the container as it lands, so each task adds its own step kind to the regression driver — one file per kind, `step/transport.rs`, `step/channel.rs`, `step/probe.rs`, `step/upload.rs`, `step/bootstrap.rs`, `step/manager.rs`, whose stubs the scaffold declared and `scenario-driver` dispatches to.

**Every timing is a field.** `SshOptions`, `ChannelOptions`, `BackoffPolicy` and `ManagerOptions` carry every interval, deadline and cap this plan names, with the constants as defaults, and every step kind exposes them in its table — a dead-link scenario waits two seconds for a pong, not ten, and a reconnect scenario backs off in hundreds of milliseconds, not seconds. Failures in this plan are user-facing. Every error type carries which host, which stage, and what the remote said. A `ConnectionFailed` with no detail is not finished work.

## 0020 — SSH Transport

### `ssh-control-master`

`crates/iznik-client/src/transport/mod.rs` and `ssh.rs`:

- `pub struct ClientRuntimePaths { pub directory: PathBuf, pub control_directory: PathBuf, pub log: PathBuf }` with `resolve()`: `$XDG_RUNTIME_DIR/iznik-client/`, else `$TMPDIR/iznik-client-<user_id>/`. Control sockets are named by a short hash of the alias because a unix socket path is limited to 104 bytes on macOS.
- `pub enum Transport { Ssh(SshTransport), Local { socket: PathBuf } }` with `Transport::for_alias(alias: &str, paths: &ClientRuntimePaths, options: SshOptions) -> Transport`: `unix:<path>` is `Local`, everything else is `Ssh`. `Local` connects straight to the daemon's socket; there is no relay to start because the tests that use it own the daemon.
- `pub struct SshOptions { pub askpass_program: Option<PathBuf>, pub control_persist: Duration (CONTROL_PERSIST, 600 seconds), pub server_alive_interval: Duration (SERVER_ALIVE_INTERVAL, 5 seconds), pub server_alive_count_maximum: u32 (SERVER_ALIVE_COUNT_MAXIMUM, 3), pub connect_timeout: Duration (CONNECT_TIMEOUT, 15 seconds) }`.
- `pub struct SshTransport` with `pub async fn spawn(&self, remote_command: &[String]) -> Result<SshChild, SshError>`: the system `ssh` through `tokio::process` with `-o ControlMaster=auto`, `-o ControlPersist=<control_persist>`, `-o ControlPath=<control_directory>/<hash>`, `-o ServerAliveInterval=…`, `-o ServerAliveCountMax=…`, `-o ConnectTimeout=…`, then the alias, then the command. `askpass_program` sets `SSH_ASKPASS` and `SSH_ASKPASS_REQUIRE=force` so an interactive prompt goes to the application's helper. iznik passes **no** `User`, `Port`, `IdentityFile`, `ProxyJump`, `HostName` or any option a user could have configured; a test asserts the argument vector against that list.
- `close_master(&self)` runs `ssh -O exit`.
- `pub enum SshError { Unreachable { host, detail }, AuthenticationFailed { host, detail }, HostKeyChanged { host, detail }, RemoteCommandFailed { host, status, stderr }, Spawn { detail }, Timeout { host, stage } }`, classified from `ssh`'s stderr and exit status by a pure `classify(status, stderr) -> SshError` tested against captured outputs — a changed host key in particular demands an alarming, specific, actionable message.
- `crates/iznik-regression/src/step/transport.rs` implements `[steps.transport]`: `alias`, `command`, `connect_timeout_seconds`, `expect` (`ok`, `unreachable`, `authentication-failed`, `host-key-changed`, `remote-command-failed`), `check_master` (asserts `ssh -O check` reports a live master and that a second command completes faster than the first) and `close_master`.

### `remote-channel`

`crates/iznik-client/src/transport/channel.rs`:

- `pub struct ChannelOptions { pub ping_interval: Duration (PING_INTERVAL, 5 seconds), pub pong_deadline: Duration (PONG_DEADLINE, 10 seconds), pub open_deadline: Duration (OPEN_DEADLINE, 30 seconds) }`.
- `pub struct RemoteChannel` with `open(transport: &Transport, server: Option<&Path>, options: ChannelOptions) -> Result<RemoteChannel, ChannelError>` — over `Ssh`, running `<server> --stdio` through the transport; over `Local`, connecting to the socket — which performs the `Hello` exchange with the crate version and `Capabilities::ZSTD | RESUME`, refuses a mismatched protocol version as `ChannelError::ProtocolVersion { host, server }`, and rebuilds its `FramedLink` through `iznik_link::compression::compressed` from the plain link's parts when both sides advertised `ZSTD`; then `send(&mut self, channel: u8, payload: &[u8])`, `next(&mut self, deadline) -> Result<Frame, ChannelError>`, and `close`, built on the link's split halves with the liveness pings on a task of their own. One channel, not many: several SSH channels would share one TCP connection and inherit head-of-line blocking with none of the scheduler's control.
- Liveness: a `Ping` every `ping_interval` with `pong_deadline` on top of `ServerAlive`; a missed deadline is `ChannelError::Dead { host, silent_for }` surfaced immediately rather than a TCP timeout that can run for minutes.
- `crates/iznik-regression/src/step/channel.rs` implements `[steps.channel]`: `alias`, `server`, the `client` step's `actions` vocabulary, `ping_interval_milliseconds`, `pong_deadline_milliseconds`, and `expect_dead_within_milliseconds`.

## 0021 — Bootstrap

### `host-probe`

`crates/iznik-client/src/bootstrap/probe.rs`: `pub async fn probe(transport, deadline) -> Result<HostProbe, ProbeError>` runs one remote shell script — because latency to a distant host is the dominant cost — that prints `uname -s -m`, whether `tic` is on the path, the installed server's `--version` line if any, whether the terminfo is installed, `$XDG_DATA_HOME`, `$HOME`, `$XDG_RUNTIME_DIR`, and a writability check of each prefix candidate; `parse(output) -> Result<HostProbe, ProbeError>` is pure and tested against synthetic outputs. `pub struct HostProbe { pub operating_system: OperatingSystem, pub architecture: Architecture, pub server: Option<InstalledServer { crate_version, protocol_version }>, pub terminfo_installed: bool, pub tic_available: bool, pub prefix: PathBuf }`. The prefix falls back through `$XDG_DATA_HOME/iznik`, `~/.local/share/iznik`, and the runtime directory, and the chosen one is reported. An unsupported operating system or architecture is `ProbeError::Unsupported { operating_system, architecture }`. `crates/iznik-regression/src/step/probe.rs` implements `[steps.probe]`: `alias` and an `expect` table over the probe's fields.

### `terminfo-asset`

`crates/iznik-client/assets/xterm-ghostty.terminfo` is the terminfo source for the terminal the application renders with, obtained with `infocmp -x xterm-ghostty` from the ncurses terminfo database — ncurses 6.5 and later ship the entry, and this machine's `ncurses-base` 6.6 does — with the ncurses version, the machine and the date recorded in `crates/iznik-client/src/bootstrap/terminfo.rs`, which exposes it as `pub const XTERM_GHOSTTY_TERMINFO: &str`. Its acceptance is that `tic -x` compiles it and the compiled entry advertises 24-bit color and styled underlines.

### `payload-upload`

`crates/iznik-client/src/bootstrap/upload.rs`: `pub struct Artifact { pub triple: String, pub path: PathBuf, pub digest: [u8; 32] }` and `pub struct ArtifactSet` loaded from a directory laid out as `xtask distribution` and `stage` lay it out, one `<triple>/iznik-server` per triple, each digest computed from the bytes on load — the bundled server's version is the client's own crate version and `PROTOCOL_VERSION`, because both are built from one workspace, so no manifest is read. `pub const REMOTE_UPLOAD_SCRIPT: &str` is the one remote script, exposed so a scenario can drive it directly: it removes any stale `.partial-*` under `<prefix>/bin/`, reads the artifact from its standard input in `UPLOAD_CHUNK_LENGTH` (1 MiB) chunks — no second connection, no `scp`, no dependency on `sftp` — into `<prefix>/bin/.partial-<random>`, verifies its SHA-256 against the digest the client passed with `sha256sum` or `shasum -a 256` as the probed operating system provides, `fsync`s, marks it executable, and renames it into place, so a link that drops mid-upload leaves nothing at the final name. `pub async fn upload(transport, artifact: &Artifact, probe: &HostProbe, deadline) -> Result<Installed, UploadError>` runs it; when `tic` is available it then writes the terminfo source to a temporary file and compiles it with `tic -x -o <prefix>/terminfo`, and when it is not, the server is told no terminfo directory exists and panes get `xterm-256color`. `crates/iznik-regression/src/step/upload.rs` implements `[steps.upload]`: `alias`, `artifacts` (defaulting to `/iznik/distribution`), and an `expect` over the installed path and the terminfo directory.

### `remote-launch`

`crates/iznik-client/src/bootstrap/mod.rs` and `launch.rs`: `pub async fn bootstrap(transport, artifacts: &ArtifactSet, options: &BootstrapOptions, deadline) -> Result<Bootstrapped, BootstrapError>` — probe; decide `Decision::{UpToDate, Install, UpgradeAvailable { installed, bundled }, Unsupported}`; upload on `Install`; open the channel through `<prefix>/bin/iznik-server --stdio` (which starts the daemon on first use); handshake; take a snapshot. A matching version skips the upload entirely and completes under `FAST_RECONNECT_BUDGET` (2 seconds) in the container. On `UpgradeAvailable` the connection proceeds with the installed daemon and the state carries the offer; `pub async fn upgrade(transport, artifacts, force: bool, deadline) -> Result<(), UpgradeError>` refuses with `UpgradeError::LivePanes { count }` when the snapshot shows panes and `force` is false, and otherwise runs `iznik-server --stop`, uploads, and reconnects. `pub async fn uninstall(transport, deadline)` stops the daemon and removes the prefix and the runtime directory: a tool that installs binaries on other people's machines owes them a clean way to take them off. `BootstrapError` carries the stage — `Probe`, `Upload`, `Launch`, `Handshake` — and the remote's words.

A scenario cannot build an older server, so it installs an older-looking one: a shell shim at `<prefix>/bin/iznik-server` that answers `--version` with `iznik-server 0.0.1 protocol 1` and `exec`s the real binary for everything else. The probe sees an older version, the decision is `UpgradeAvailable`, and a forced upgrade replaces the shim with the artifact, after which the real version answers. `crates/iznik-regression/src/step/bootstrap.rs` implements `[steps.bootstrap]`: `alias`, `action` (`bootstrap`, `upgrade`, `uninstall`), `force`, and an `expect` over the decision, the error stage, and the live-pane count.

## 0022 — Client Model

### `client-model`

`crates/iznik-client/src/model.rs`: `pub struct ClientModel { pub hosts: BTreeMap<HostId, HostView> }`, `pub struct HostView { pub model: HostModel, pub subscriptions: BTreeMap<PaneId, Subscription>, pub focus: Option<PaneId>, pub pending: Vec<PendingCommand> }`, `pub struct Subscription { pub channel: u8, pub cursor: Sequence, pub credit_outstanding: u64 }`. It performs no I/O and holds everything the client needs to resume: for every subscribed pane, the sequence it holds.

### `client-reducer`

`crates/iznik-client/src/reduce.rs`: `pub fn reduce(model: &mut ClientModel, host: &HostId, message: &ToClient) -> Vec<Effect>` applies a `Snapshot` by replacement, a `Delta` through the protocol's reconciler — `GenerationGap` yields `Effect::RequestSnapshot` — a `PaneChannel` by opening a subscription at its sequence, pane bytes by advancing the cursor, a `PaneDetached` by dropping the subscription and yielding `Effect::ReleaseChannel`, a `Screen` by resetting the cursor to its sequence and yielding `Effect::Screen`, and `CommandResult` and marks by yielding notifications. `pub enum Effect { RequestSnapshot, ReleaseChannel { channel }, Screen { pane, sequence }, Notify(Notification) }`. Routing by host happens before anything else, and the convergence property from plan 0003 carries over unchanged because the reconciler and the generator are the same code.

### `optimistic-commands`

`crates/iznik-client/src/commands.rs`: `pub fn submit(view: &mut HostView, command: SessionCommand, now: Instant) -> Submission` applies the local effect at once for `RenameSession`, `RenameTab`, `CloseSession`, `CloseTab`, `ClosePane` and `ReorderTabs` — the commands whose local effect is unambiguous — records a `PendingCommand { id, command, rollback: HostModel, submitted_at }`, and leaves creation and `MovePane` and `SetLayout` to wait one round trip, because inventing a placeholder to reconcile later is more flicker than waiting. `confirm(view, result)` retires a pending entry on `Applied` and rolls back on `Rejected`; `expire(view, now, timeout)` rolls back and yields `Notification::CommandTimedOut` after `timeout` — `PENDING_COMMAND_TIMEOUT` (5 seconds) by default — because a UI element stuck in a state the server never agreed to is worse than a visible failure. The authoritative delta always wins: after rollback, the server's state stands. Pure functions over `HostView` and `Instant`, landed before the manager that calls them.

## 0023 — Multi-Host

### `host-identity-and-state`

`crates/iznik-client/src/host/identity.rs` and `state.rs`: `pub struct HostId(pub String)` — the user's alias, what they typed and what they will recognize, with `local_socket(&self) -> Option<PathBuf>` recognizing the `unix:` form; `pub struct GlobalPaneId { pub host: HostId, pub pane: PaneId }` with the canonical `iznik://<host>/<pane>` rendering and parser used in logs, diagnostics and the client contract. `pub enum HostState { Disconnected, Probing, Bootstrapping { stage }, Connecting, Connected { server_version, upgrade: Option<UpgradeOffer> }, Reconnecting { attempt, retry_at }, Failed { error, retry_at } }` and `pub struct HostStateMachine` with `new(backoff: BackoffPolicy)` and `on(&mut self, event: HostEvent, now: Instant) -> Vec<Action>` — a pure state machine with exponential backoff from `BackoffPolicy::initial` (`BACKOFF_INITIAL`, 1 second) to `maximum` (`BACKOFF_MAXIMUM`, 60 seconds) with jitter from a seeded source, tested as a table of `(state, event) → (state, actions)`.

### `connection-manager`

`crates/iznik-client/src/host/manager.rs`: `pub struct ManagerOptions { pub artifacts_directory: PathBuf, pub runtime_paths: ClientRuntimePaths, pub ssh: SshOptions, pub channel: ChannelOptions, pub backoff: BackoffPolicy, pub pending_command_timeout: Duration, pub log_path: Option<PathBuf> }` and `pub struct HostManager` with `new(options: ManagerOptions) -> Result<HostManager, ManagerError>` — it owns its runtime, so its methods are plain calls from any thread — `add_host(&self, alias)`, `remove_host`, `reconnect`, `upgrade(alias, force)`, `uninstall`, `events() -> mpsc::Receiver<ManagerEvent>`, `model() -> ClientModel` (a snapshot), and the per-pane operations plan 0006 wraps — `subscribe`, `unsubscribe`, `input`, `resize`, `focus`, `credit`, `command` through `commands::submit`, with `expire` driven by a timer. One task per host runs its state machine: bootstrap, channel, handshake, snapshot, then the loop; on `ChannelError::Dead`, `Reconnecting` with backoff, and on reconnection a `Resume` for every subscription at the cursor the model holds — which is the mechanism that keeps a pane's bytes across a drop. Isolation is the requirement: no lock held across a network call, no aggregate operation that waits on the slowest host, no retry storm when four hosts fail at once because a laptop closed.

## 0024 — End to End

### `end-to-end-ssh`

`crates/iznik-regression/src/step/manager.rs` implements `[steps.manager]`: a `HostManager` inside the engine container with `artifacts` pointing at `/iznik/distribution`, every `ManagerOptions` timing as a field of the table, and actions `add_host`, `await_state`, `command`, `subscribe`, `input`, `resize`, `focus`, `capture_to`, `screen_to`, `await_delta`, `upgrade`, `uninstall` and `expect_reassembly`. The scenarios under `regression/scenarios/end-to-end-ssh/` run with `hosts = 2`: bootstrap both from nothing; a session and a typed line on each; a network fault on `host1` while `host0` keeps echoing within the latency budget; reconnection on `host1` with byte-exact continuation through the oracle and the same `GlobalPaneId`, with backoff in hundreds of milliseconds; an upgrade refused for live panes and forced, against the shim; an uninstall that leaves nothing. This is the plan's proof and the product's first end-to-end run, and every scenario in it has a budget under two minutes.
