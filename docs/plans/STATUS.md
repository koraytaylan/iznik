# Plans — roll-up board

One row per plan. Task status is authored in each plan's `tasks/*.md` frontmatter and summarized by its `STATUS.md`.

Every plan from 0001 onward proves its runtime claims against the two-container Podman regression suite built in plan 0001, whose scenarios are ordinary nextest tests that run in parallel. A claim declared in `regression/claims/<task-id>.toml` without a registered passing proof fails `xtask claims coverage`, and a branch that changes product code without declaring claims fails `xtask claims verify`. Every task's done-when is a bounded command: a gate that does not finish inside its deadline is a failed gate that names the step it was running, never a wait — and a gate that is slow is a bug.
